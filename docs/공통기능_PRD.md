## 1. 배경 및 문제 정의

여러 지점이 하나의 시스템을 공용으로 쓰는 구조로 확정되면서(부품관리시스템_PRD.md §11-15), "로그인해서 내 지점 데이터를 보는" 기반 자체가 별도로 필요해졌다. 또한 RO의 담당 엔지니어, 지점재고공유의 재고 등록 지점 등 여러 기능이 "지점"과 "엔지니어"라는 마스터 데이터를 전제로 하고 있어, 이 데이터를 어떻게 만들고 관리할지 정의가 필요하다.

---

## 2. 목표

| 목표 | 설명 |
|---|---|
| 1차 목표 | 지점이 최소한의 절차로 로그인하고 각자 데이터를 안전하게 분리해서 쓸 수 있게 한다 |
| 2차 목표 | 지점 상세정보와 엔지니어 정보를 지점이 스스로 유지·관리할 수 있게 한다 |

---

## 3. 대상 사용자

| 역할 | 시스템에서 하는 일 |
|---|---|
| 서비스 운영자 | 신규 지점 온보딩 시 지점명과 기본 비밀번호를 발급 (앱 밖에서 처리) |
| 지점 (로그인한 직원 누구나) | 로그인, 비밀번호 변경, 지점 상세정보 관리, 소속 엔지니어 등록·관리 |

---

## 4. 용어 정의

| 용어 | 의미 |
|---|---|
| 지점 계정 | 지점 하나당 하나씩 존재하는 로그인 단위. 직원 개인 계정이 아님 |
| 기본 비밀번호 | 운영자가 신규 지점 온보딩 시 발급하는 초기 비밀번호 |
| 엔지니어 | RO의 담당 엔지니어 필드에서 선택되는 값. 로그인 계정이 아니며 이름·전화번호만 가짐 |

---

## 5. 핵심 워크플로우

```
① 운영자: 신규 지점 온보딩 시 지점명 + 기본 비밀번호만 시스템에 등록
      │  (앱 내 화면 없음. 결제/구독 연동 온보딩 전까지는 백엔드에서 직접 처리, §9 참고)
      │
② 지점: 로그인 화면에서 지점명 선택 + 기본 비밀번호로 최초 로그인
      │
③ 지점: 설정 화면에서 비밀번호 변경 (권장, 강제 아님 — §10-1 확인 필요)
      │
④ 지점: 설정 화면에서 지점 상세정보(전화번호, 주소) 입력/수정
      │  → 주소는 자동 지오코딩되어 좌표로 저장 (지점재고공유_PRD.md §7 INV-07과 동일한 지오코딩 사용)
      │
⑤ 지점: 같은 설정 화면 내에서 소속 엔지니어 등록·수정·삭제
      │  → 등록된 엔지니어는 부품관리시스템의 RO 접수 화면에서 "담당 엔지니어" 선택지로 노출됨
```

**핵심 설계 포인트**
- 지점 등록 자체(부트스트랩)는 앱 안에 화면을 두지 않는다. 초기 규모가 작고, 향후 결제/구독 기능이 생기면 그 가입 흐름에 자연스럽게 흡수될 수 있어 지금 단계에서 미리 화면을 만들지 않는다
- 비밀번호 변경, 지점 상세정보 관리, 엔지니어 관리는 모두 **같은 설정 화면** 안에 모아둔다 (탭 또는 섹션 구분)
- 엔지니어는 로그인 계정이 아니다. RO에서 "담당 엔지니어"를 고르기 위한 조회용 데이터일 뿐이다

## 7. 기능 요구사항 (FR)

기존 문서들의 FR/INV 번호와 겹치지 않도록 `COM-` 접두사를 사용한다.

| ID | 요구사항 |
|---|---|
| COM-01 | 서비스 운영자는 신규 지점을 지점명과 기본 비밀번호로 등록할 수 있다 (앱 내 화면이 아닌 백엔드 처리) |
| COM-02 | 로그인 화면에서 등록된 지점 목록 중 하나를 선택하고 비밀번호를 입력해 로그인할 수 있다 |
| COM-03 | 로그인 세션은 로그아웃 전까지 별도 만료 없이 유지된다 |
| COM-04 | 로그인한 지점은 설정 화면에서 비밀번호를 변경할 수 있다 |
| COM-05 | 로그인한 지점은 설정 화면에서 자신의 지점 상세정보(전화번호, 주소)를 입력·수정할 수 있다. 주소는 자동으로 지오코딩되어 좌표로 저장된다 |
| COM-06 | 로그인한 지점은 설정 화면에서 자신의 소속 엔지니어를 이름, 전화번호와 함께 등록·수정할 수 있다 |
| COM-07 | 엔지니어는 로그인 계정이 아니며, 부품관리시스템의 RO 접수/수정 화면에서 담당 엔지니어 선택지로 노출된다 |
| COM-08 | 엔지니어는 완전히 삭제되지 않고 비활성화만 가능하다. 비활성화된 엔지니어는 새 RO의 담당 엔지니어 선택지에는 더 이상 노출되지 않지만, 이미 그 엔지니어가 배정된 과거 RO 기록은 그대로 유지된다 (§10 확정) |
| COM-09 | 로그인 화면의 지점 선택은 검색 가능한 드롭다운(타이핑 필터링)으로 제공된다. 지점 수가 최대 수백 개 규모이므로 단순 스크롤 목록으로는 찾기 어렵기 때문이다 (§10 확정) |

## 9. 범위 외 (Out of Scope, v0.1 기준)

- 결제/구독과 연동된 지점 온보딩 (향후 결제 시스템 도입 시 재검토. 실제 사업화 시 PG 연동이 필요할 수 있음)
- 개인별 계정, 역할 기반 접근 권한 (부품관리시스템_PRD.md §11-15 참고)
- 비밀번호 찾기/재설정 자동화 기능
- 고객센터/문의 응대용 어드민 페이지 (관리자가 운영자 본인 1인이라, 당분간은 Slack·Notion·구글시트·이메일 등 기존 툴로 응대. 사업화 이후 문의량이 늘면 재검토)

## 10. 확인이 필요한 사항 (Open Questions) — 확정 내역

1. ~~엔지니어 삭제 시 과거 RO 무결성~~
   → **확정: 완전 삭제 기능은 두지 않고 비활성화만 가능하게 한다. 비활성화된 엔지니어는 새 RO 배정 선택지에서만 빠지고, 과거 RO 기록은 그대로 유지된다**
2. ~~로그인 화면 지점 선택 UI~~
   → **확정: 지점 수가 최대 수백 개 규모라 검색 가능한 드롭다운(타이핑 필터링)으로 제공한다**

### 10-1. 최초 로그인 시 비밀번호 변경 강제 여부 — 확인 필요

- 기본 비밀번호로 로그인한 뒤 변경을 강제할지, 권장만 하고 안 바꿔도 계속 쓸 수 있게 둘지 미정

### 10-2. 비밀번호 분실 시 처리 방식 — 확인 필요

- 운영자에게 문의해서 재발급받는 방식으로 충분한지, 자체 재설정 기능이 필요한지 미정

### 10-3. 지점명 변경 필요 시 처리 방식 — 확인 필요

- 지점명이 로그인 식별자를 겸하므로, 변경이 필요할 때 지점이 직접 바꿀 수 있게 할지 운영자만 가능하게 할지 미정
