## 1. 배경 및 문제 정의

### 1-1. 현재 상황
- 손님에게 필요한 부품이 모비스에 재고가 없을 때, 지점은 인근 지점에 개별로 전화를 돌려 재고 여부를 확인함
- 인근 지점에도 없으면 손님에게 부품이 없어 수리가 어렵다고 안내하고 돌려보내는 경우도 있음
- 이 개별 전화 확인 방식이 비효율적이고, 각 지점은 활용되지 못한 채 쌓여만 가는 **장기재고**를 계속 보유하게 됨

### 1-2. 핵심 문제
> "어딘가에는 있는 재고인데, 그걸 찾는 방법이 전화 돌리기뿐이다"

전국 단위로 보면 필요한 부품이 이미 어느 지점엔가 있을 가능성이 높지만, 그걸 확인할 방법이 개별 전화 연락뿐이라 실제로는 거의 활용되지 못함. 이 시스템의 목적은 **전국 지점의 장기재고를 한 곳에서 검색 가능하게 만들어 재고 소진과 신속한 고객 응대를 동시에 해결하는 것**임.

## 2. 목표

| 목표 | 설명 |
|---|---|
| 1차 목표 | 전국 지점의 장기재고를 등록하고 검색할 수 있게 하여 재고 소진율을 높인다 |
| 2차 목표 | 부품이 급하게 필요한 지점이 모비스 재주문 없이 인근 지점 재고로 신속하게 대응할 수 있게 한다 |

## 4. 용어 정의

| 용어 | 의미 |
|---|---|
| 지점(Branch) | 이 시스템을 사용하는 개별 대리점 |
| 장기재고 | 오랫동안 사용되지 않고 지점에 남아있는 부품 재고 |
| 재고 항목 | 지점이 등록한 개별 장기재고 (부품번호, 부품명, 수량 단위) |
| 재고 확보 | 검색으로 찾은 다른 지점의 재고를 전화로 조율해 실제로 가져오기로 정하는 것 |

## 5. 핵심 워크플로우

```
① A지점: 모비스에 필요 부품 재고 없음 확인
      │
② A지점: 재고 검색 (독립 재고 페이지의 [전체 검색] 탭 또는 RO 접수/수정 화면에서 팝업으로 띄우는 검색창)
      │  → 검색 결과: 재고 보유 지점 목록, 요청 지점의 등록 주소 기준 가까운 순 정렬
      │  → 표시 항목: 부품명, 재고 수량, 지점명, 전화번호, 주소
      │
③ A지점: 검색 결과에 나온 전화번호로 직접 연락해 재고 확보 여부 확인 (시스템 밖 전화 조율)
      │
      ├─ 확보 실패(재고 없음/거절) → 다른 지점 검색 계속하거나 모비스 재주문 절차로 복귀
      │
      └─ 확보 성공
              │
         ④ A지점: RO 접수/수정 화면에서 해당 부품의 출처를 "OO지점 재고"로 선택
              │
         ⑤ 시스템: 즉시 B지점(재고 보유 지점)의 재고 수량을 자동 차감
              │
         ⑥ A지점: 그 부품은 확보 완료로 표시되어, 이후 기존 부품관리시스템 PRD의
                  입고·안내·예약 플로우와 동일하게 진행
```

**핵심 설계 포인트**
- 재고 검색은 순수 정보 조회다. 지점 간 실제 확보 조율(연락)은 시스템 밖에서 전화로 이뤄진다
- 재고 차감은 자동이지만, 그 실행 트리거는 "RO 화면에서 출처 지점을 선택"하는 사람의 행위다. 시스템이 전화 통화 결과를 스스로 판단해 임의로 차감하지 않는다
- 재고 등록은 지점이 자율적으로 한다. 장기재고가 생겼을 때 수시로 등록하는 방식이며, 별도 승인 절차는 없다

## 6. 화면에 표시할 데이터 항목

독립 재고 페이지는 탭으로 구성한다: **[전체 검색]** **[내 지점 재고]**. 두 탭 모두 같은 목록 컴포넌트를
재사용하며, "내 지점 재고" 탭에서만 행마다 수정·삭제 버튼이 추가로 표시된다 (§11 확정. 이 부품관리시스템
PRD의 RO 목록 화면이 진행중/작업완료/반품필요 탭 구조를 쓰는 것과 동일한 패턴).

## 7. 기능 요구사항 (FR)

기존 `부품관리시스템_PRD.md`의 FR 번호와 겹치지 않도록 `INV-` 접두사를 사용한다.

| ID | 요구사항 |
|---|---|
| INV-01 | 직원 누구나 소속 지점의 장기재고를 부품번호, 부품명, 수량과 함께 등록할 수 있다 (§11 확정) |
| INV-02 | 직원 누구나 등록된 재고를 부품번호 또는 부품명으로 검색할 수 있다 (§11 확정) |
| INV-03 | 검색 결과는 요청 지점 기준 가까운 지점 순으로 정렬되어 표시된다 (부품번호, 부품명, 재고 수량, 지점명, 전화번호, 주소 포함) |
| INV-04 | RO 접수/수정 화면에서 페이지 이동 없이 위 재고 검색을 수행할 수 있다. 표시할 정보(부품번호·부품명·재고 수량·지점명·전화번호·주소)가 많아 도로명주소 검색처럼 팝업(모달)으로 띄운다 (§11 확정) |
| INV-05 | RO 화면에서 특정 지점의 재고를 사용하기로 선택하면, 해당 지점의 재고 수량이 자동으로 차감된다 |
| INV-06 | 지점은 본인 지점이 등록한 재고만 [내 지점 재고] 탭에서 수정·삭제할 수 있다. 다른 지점 재고는 조회만 가능하다 (§11 확정) |
| INV-07 | 지점 등록/수정 시 입력한 주소는 시스템이 자동으로 지오코딩해 좌표로 변환한다. 직원이 좌표를 직접 입력하지 않는다 (§11 확정) |
| INV-08 | 재고 수량이 0이 되어도 데이터는 삭제되지 않고 유지되며, [전체 검색] 탭 결과에서만 제외된다. [내 지점 재고] 탭에서는 계속 표시된다 (§11 확정) |

## 8. 비기능 요구사항 (NFR)

| ID | 요구사항 |
|---|---|

## 9. 성공 지표 (KPI)

- 등록된 장기재고 중 실제로 타 지점에서 소진된 비율
- 모비스 재주문 대신 지점 간 재고로 해결된 건수

---

## 10. 범위 외 (Out of Scope, v0.1 기준)

- 재고 이동(배송) 자체의 물류 처리 — 지점 간 직접 조율
- 지점 간 비용 정산 기능. 물물교환처럼 정산 없이 진행하며, 필요 시 지점끼리 알아서 처리 (§11 확정)
- 재고 확보 요청에 대한 시스템 내 승인/거절 워크플로우 (오프라인 전화 조율로 충분하다고 판단)
- 본사/전체 관리자용 전국 재고 현황 대시보드 (§11 확정, 각 지점이 검색으로 확인하는 것으로 충분)

## 11. 확인이 필요한 사항 (Open Questions) — 확정 내역

1. ~~재고 등록/검색 권한~~
   → **확정: 직원 누구나 가능. 역할별로 나누지 않는다**
2. ~~비용 정산 여부~~
   → **확정: 정산 기능 없음. 물물교환처럼 정산 없이 진행하며, 필요하면 지점끼리 알아서 처리한다**
3. ~~지점 좌표(위치) 확보 방식~~
   → **확정: 자동 지오코딩. 지점 등록/수정 시 입력한 주소를 시스템이 좌표로 자동 변환하며, 직원이 좌표를 직접 입력하지 않는다**
4. ~~본사/전체 관리자 화면 필요 여부~~
   → **확정: 불필요. 각 지점이 검색으로 확인하는 것으로 충분**
5. ~~내 지점이 등록한 재고를 수정·삭제하는 화면 위치~~
   → **확정: 독립 재고 페이지 안에 [전체 검색] / [내 지점 재고] 두 탭으로 구성. 별도 페이지를 새로 만들지 않고 같은 목록 컴포넌트를 재사용해 "내 지점 재고" 탭에서만 수정·삭제 버튼을 표시** (부품관리시스템 PRD의 RO 목록 탭 구조와 동일한 패턴)
6. ~~정렬 기준점~~
   → **확정: 요청 지점의 등록 주소(지오코딩된 좌표) 기준. 사용자 GPS 현재 위치는 쓰지 않는다**
7. ~~재고 수량 0 처리~~
   → **확정: 데이터는 삭제하지 않고 유지. [전체 검색] 탭 결과에서만 제외되고, [내 지점 재고] 탭에서는 계속 표시된다**
8. ~~RO 화면 재고 검색 UI 형태~~
   → **확정: 팝업(모달)으로 띄운다. 표시 정보(부품번호·부품명·재고 수량·지점명·전화번호·주소)가 많아 페이지 안에 인라인으로 넣기엔 부담스러워, 도로명주소 검색 팝업과 같은 패턴을 쓴다**
